# Code Of Conduct

NoteSense is currently an owner-maintained portfolio product, but public discussion should still be respectful, focused, and safe for people who want to learn from or contribute to the work.

## Standard

- Be kind, specific, and constructive in issues, pull requests, reviews, and discussions.
- Assume good intent while still being clear about bugs, risks, and tradeoffs.
- Respect different experience levels, musical backgrounds, accessibility needs, and communication styles.
- Keep feedback about the work rather than the person.
- Help keep the project aligned with its local-first, privacy-respecting, foundation-first goals.

## Unacceptable Behavior

- Harassment, threats, personal attacks, or sustained disruption.
- Discriminatory language or behavior.
- Sexualized, violent, or otherwise unsafe content.
- Publishing private information without permission.
- Pressuring the owner or contributors to bypass review, security, privacy, licensing, or release expectations.

## Reporting

If a conduct concern can be handled publicly, open a GitHub issue with factual context and links to the relevant discussion.

If the concern includes private information, safety risk, abuse, security, or privacy impact, report it through the private contact path in [SECURITY.md](SECURITY.md) instead of posting details publicly.

## Enforcement

The project owner may remove comments, close issues or pull requests, block participation, or take other reasonable action to protect the project and its participants.

Enforcement decisions should be proportionate, documented when appropriate, and aligned with the legal, security, privacy, review, and release expectations in this repository.

## Scope

This Code of Conduct applies to participation in the NoteSense repository and project-managed spaces. It does not change the project license, grant source-code rights, or create a formal support commitment.

## Change Rules

- Keep [docs/LEGAL.md](docs/LEGAL.md), [CONTRIBUTING.md](CONTRIBUTING.md), the pull request template, release guidance, and legal checks aligned when conduct or contributor-community expectations change.
- Run `npm run legal:check` and `npm run docs:check` after conduct-policy changes.
